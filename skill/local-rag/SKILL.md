# Local RAG

요청을 아래 일 중 하나로 분류해서 처리하세요. 사용자는 개발자가 아닐 수 있으니, 명령은 직접 실행하고 결과를 쉬운 말로 알려 주세요.
이 스킬은 GitHub Copilot, Claude Code, Codex 등 어느 AI 도구에서나 같은 방법으로 씁니다.

## 공통 규칙

- 명령은 항상 `rag`라는 이름으로 실행하세요. 파이프(`|`)나 리디렉션(`>`)은 붙이지 마세요.
- `rag`를 찾지 못한다는 오류가 나면, 이 파일 끝의 '이 PC의 rag 실행 파일' 절에 적힌 전체 경로로 같은 명령을 다시 실행하세요. 그 절이 없거나 전체 경로도 없으면, 로컬 RAG 키트 폴더(local-rag 또는 github-copilot-local-rag-main)를 AI 도구에서 열고 "설치해 줘"라고 요청하라고 안내하세요.
- 확인이 필요할 때는 질문 도구(선택지 창 등)에 기대지 말고, 답변에 물어볼 내용을 쓰고 그 차례를 마치세요. 사용자가 답하면 이어서 진행합니다. 질문 도구가 "사용자가 답할 수 없다"고 돌려주면 확인을 받지 못한 것으로 봅니다.
- 지우거나 원본 폴더를 바꾸는 명령(`rag remove`, `rag move`)은 미리보기를 보여 주고 확인을 받은 뒤에만 실행하세요.
- 사용자가 "docs 컬렉션"처럼 폴더 이름으로 말하면, `rag list`에서 원본 폴더가 지금 연 프로젝트의 그 폴더인 컬렉션을 고르세요. 컬렉션 이름은 '프로젝트-폴더-해시' 모양이라 폴더 이름과 다릅니다.
- 명령 출력의 경고와 `[컬렉션]`으로 시작하는 안내 줄은 답 앞에 그대로 알려 주세요.
- 출력 글자가 깨져 보이면 추측해서 답하지 말고 `rag check`를 실행해 그 결과를 알려 주세요.
- 원인을 모르는 오류가 나면 `rag check`로 점검하고, `[실패]`와 `[확인 필요]` 줄의 "다음에 할 일"을 알려 주세요.

## 1. 폴더를 RAG로 만들기

예: "docs 폴더 파일 모두를 RAG로 만들어 줘", "`[경로]`를 RAG로 만들어 줘", "wiki 폴더를 Google 모델로 RAG 만들어 줘"

1. 상대 경로는 지금 연 작업 폴더 기준의 절대 경로로 바꾸세요. 경로가 없거나 모호하면 실행하지 말고 물어보세요.
2. `rag scan "<절대 경로>"`로 대상 파일 수, 용량, 예상 시간, 건너뛸 파일, 제안 이름을 확인하세요.
   - 이름은 '프로젝트-폴더-해시' 모양으로 제안됩니다(예: `memo1-wiki-3f9a`). 해시는 폴더 경로로 만들어서, 다른 프로젝트의 같은 이름 폴더와 겹치지 않습니다. 사용자가 이름을 정하지 않았으면 제안 이름을 그대로 쓰세요.
   - "이미 있는 컬렉션"이 나오면 새로 만들지 않고 그 컬렉션을 갱신한다고 알리세요.
3. 아래 중 하나라도 해당하면 색인하지 말고, 스캔 결과와 함께 물어본 뒤 차례를 마치세요.
   - 예상 시간이 2분을 넘음
   - 빌드 결과물, 의존성 폴더, 비밀 정보가 있을 만한 파일(`.env`, 인증서, 비밀번호 목록 등)이 대상에 들어 있음. 빼자고 제안하고, 동의하면 `--exclude <패턴>`으로 다시 스캔하세요.
   - 네트워크 드라이브이거나 대상 파일이 수천 개. 검색할 때의 자동 갱신을 끄자고(`--auto-refresh off`) 제안하세요.
4. 해당하는 것이 없으면, 만들어 달라는 요청 자체를 확인으로 보고 바로 `rag index "<절대 경로>" --desc "<한 줄 설명>"`을 실행하세요. 설명은 폴더 내용을 보고 한 줄로 쓰세요. 사용자가 이름을 정했으면 `--name <이름>`을 붙이세요.
5. 결과와 함께 다음을 짧게 알리세요.
   - 컬렉션 이름, 파일 수, 조각 수
   - 건너뛴 파일에 `.docx`, `.pdf` 같은 문서가 있으면 지금은 읽지 못하고 마크다운으로 바꿔야 한다는 것
   - 검색하면 찾은 조각이 AI 대화로 전달된다는 것

예상 시간이 2분을 넘어 사용자가 진행하라고 하면, `rag index`를 실행하고 끝날 때까지 기다리세요. AI 도구가 오래 걸리는 명령을 중간에 끊었으면, 같은 명령을 다시 실행하면 이어서 된다고 알리고 다시 실행하세요.

## 2. 질문

예: "출장 일비 기준을 찾아 줘", "`[컬렉션]`에서 찾아 줘"

1. `rag list`의 이름, 설명, 원본 폴더를 보고 맞는 컬렉션을 골라 `rag search "<질문>" --name <이름>`으로 찾으세요. 지금 연 프로젝트의 지침 파일에 컬렉션 이름이 적혀 있으면 그 이름을 쓰고, 어느 컬렉션인지 애매하면 `--all`을 쓰세요.
2. 출력된 조각만 근거로 답하세요. 조각만으로 부족하면 결과에 나온 원본 파일의 해당 부분을 읽어도 됩니다.
3. 결과가 부족하면 질문의 표현을 바꿔 한 번 더 검색하세요. 그래도 없으면 추측하지 말고 "문서에서 찾지 못했습니다"라고 답하세요.

## 3. 갱신

요청에 담긴 조건으로 범위를 정하고, 같은 옵션에 `--dry-run`을 붙여 처리할 파일 수와 예상 시간을 먼저 확인하세요. 2분 이하면 `--dry-run`을 뺀 명령을 바로 실행하고, 넘으면 예상 시간을 알리고 물어보세요.

- 파일 지정("spec.md를 다시 인덱싱해 줘"): `rag index --name <이름> --file <파일>`
- 조건 지정("policies 폴더 문서만 갱신해 줘"): 조건을 glob 패턴으로 바꿔 먼저 보여 주고 `rag index --name <이름> --only <패턴>`
- 조건 없음("docs 컬렉션을 갱신해 줘"): `rag index --name <이름>`. 모든 파일을 확인하고 바뀐 파일만 다시 처리한다고 알리세요.
- 처음부터 다시 만들기: `rag index --name <이름> --rebuild`. 이 요청일 때만 `--rebuild`를 쓰세요.

자동 갱신이 켜진 컬렉션이면, 문서 몇 개를 고친 정도는 갱신을 요청하지 않아도 질문할 때 반영된다고 알려 주세요.

## 4. 원본 폴더를 옮겼을 때

예: "docs 폴더를 D 드라이브로 옮겼어", 또는 검색 결과 위에 "원본 폴더를 찾을 수 없어"라는 안내가 나왔을 때

1. 검색 중에 이 안내가 나왔다면, 답한 뒤에 "문서 폴더를 옮기셨나요? 새 위치를 알려 주시면 이어서 쓰도록 바꿔 드릴게요"처럼 물어보세요. 사용자에게 `rag move`를 직접 실행하라고 하지 마세요. 새 위치를 모르면 물어보세요.
2. `rag move <이름> "<새 경로>"`로 미리보기를 보여 주고 바꿔도 되는지 물어보세요. 내용이 같은 파일은 다시 임베딩하지 않는다고 알리세요.
3. 확인을 받으면 `rag move <이름> "<새 경로>" --yes`를 실행하고, 바뀐 파일이나 새 파일이 있으면 3번 갱신의 '조건 없음'으로 이어서 처리하세요.
4. 다른 폴더를 같은 이름으로 만들려다 "이미 다른 폴더를 쓰고 있습니다"가 나오면, 폴더를 옮긴 것인지 다른 폴더인지 물어보세요. 다른 폴더면 출력에 나온 다른 이름으로 만드세요.

## 5. 목록, 삭제, 자동 갱신

- 목록: `rag list`. "원본 폴더 없음"이 붙은 컬렉션이 있으면 4번을 안내하세요.
- 삭제: `rag remove <이름>`(`--yes` 없이)으로 무엇이 지워지는지 보여 주고, 원본 문서는 지우지 않는다고 알린 뒤 물어보세요. 확인을 받으면 `rag remove <이름> --yes`.
- 자동 갱신 끄기/켜기: `rag index --name <이름> --auto-refresh off` 또는 `on`.

## 6. 임베딩 모델 고르기

예: "어떤 모델을 쓸 수 있어?", "중국 모델 말고 다른 걸로 해 줘", "Google 모델로 바꿔 줘"

1. `rag models`로 후보(만든 회사와 나라, 라이선스, 크기, 받았는지, 쓰는 컬렉션)를 보여 주세요. 기본 모델은 Qwen3(Alibaba, 중국)입니다. 중국 모델을 쓸 수 없으면 Google의 EmbeddingGemma를 먼저 권하고, 각 모델의 메모(바탕 모델, 라이선스)도 함께 알려 주세요.
2. 받지 않은 모델이면 `rag models --add <모델>`로 받으세요. 앞으로 새 컬렉션의 기본으로 쓰겠다고 하면 `--default`를 붙이세요. 인터넷이 막힌 PC면 반입 준비 때 그 모델을 함께 받아 와야 한다고 알리세요.
3. 새 컬렉션만 이 모델로 만들려면 1번 절차의 `rag index`에 `--model <모델>`을 붙이세요.
4. 기존 컬렉션을 바꾸려면 `rag index --name <이름> --model <모델>`입니다. 컬렉션 전체를 다시 임베딩하므로 `rag scan`의 예상 시간을 먼저 알리고 물어보세요.

컬렉션은 만들 때 쓴 모델로 검색하므로, 컬렉션마다 모델이 달라도 됩니다.

## 7. 프로젝트에 적용, 활용 예제 만들기

예: "이 프로젝트에 적용해 줘", "local-rag를 활용하는 팀 FAQ 예제를 만들어 줘", "검색 결과를 쓰는 스크립트를 만들어 줘"

이 스킬 폴더의 [integration.md](integration.md)를 읽고 그 절차를 따르세요.

## 8. 점검

예: "로컬 RAG 점검해 줘", "rag가 이상해"

`rag check`를 실행하고, `[실패]`와 `[확인 필요]` 항목을 "다음에 할 일"과 함께 짧게 정리하세요.

## 답하는 규칙

- 답 끝에 출처로 컬렉션 이름, 파일 경로, 제목, 문서 수정일을 붙이세요.
- 같은 항목의 값이 문서마다 다르면 한쪽을 골라 단정하지 말고 두 값과 출처를 모두 보여 주세요. 어느 쪽이 최신인지는 문서 안의 시행일, 판(예: 2025년판), 개정 이력을 먼저 보고, 그런 표기가 없을 때만 문서 수정일을 참고하세요. 파일을 복사하면 수정일이 바뀔 수 있다는 점도 알려 주세요.

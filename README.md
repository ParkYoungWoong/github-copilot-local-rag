# 로컬 RAG 기본 환경

문서 폴더를 내 PC에서 RAG(검색 증강 생성)로 만들고, 어느 프로젝트에서든 AI에게 문서 내용을 물어볼 수 있게 하는 기본 환경입니다.
PC마다 한 번 설치하면, 그다음부터는 프로젝트를 열고 AI에게 요청만 하면 됩니다.
GitHub Copilot(VS Code, Copilot CLI), Claude Code, Codex처럼 스킬과 `AGENTS.md`를 읽는 AI 도구에서 같은 방법으로 씁니다.
[GitHub Copilot 업무 비서 만들기](https://www.heropy.dev/p/PgnSNw)의 '로컬 RAG'에서도 사용합니다.

준비물은 AI 도구 하나입니다. Python과 Ollama는 설치할 때 AI가 확인하고, 없으면 설치를 도와줍니다.

> AI는 이 폴더의 [AGENTS.md](AGENTS.md)를 읽고 진행합니다. Claude Code와 Gemini CLI도 `CLAUDE.md`, `GEMINI.md`를 거쳐 같은 문서를 읽습니다.

## 사용 순서

모든 일은 AI 도구에서 폴더를 열고, 채팅 입력창에 아래 요청을 입력하는 것으로 끝납니다. VS Code의 Copilot이라면 에이전트를 Agent로 둡니다.
아래에서 '키트 폴더'는 이 저장소를 받은 폴더(ZIP으로 받으면 `github-copilot-local-rag-main`, 반입용으로 복사하면 `local-rag`)를 말합니다.

| 할 일 | 여는 폴더 | AI에게 할 요청 |
| --- | --- | --- |
| 처음 설치(PC마다 한 번) | 키트 폴더 | `설치해 줘` |
| 내 프로젝트에 적용 | 내 프로젝트 | `/local-rag 이 프로젝트에 적용해 줘` |
| 활용 예제 만들기 | 예제를 만들 폴더 | `/local-rag 이걸 활용하는 팀 FAQ 예제를 만들어 줘` |
| 문서에서 찾기 | 아무 프로젝트 | `/local-rag 출장 일비 기준을 찾아 줘` |
| 상태 점검 | 아무 프로젝트 | `/local-rag 점검해 줘` |
| 사내망 반입 준비 | 키트 폴더 | `E 드라이브에 반입용으로 담아 줘` |

1. 저장소 페이지에서 `Code > Download ZIP`을 눌러 압축 파일을 받고 압축을 풉니다. 압축을 푼 `github-copilot-local-rag-main` 폴더가 키트 폴더이며, 홈 폴더 아래에 두는 것을 권합니다. Windows의 '압축 풀기'는 같은 이름의 폴더를 한 번 더 만들기도 하는데, 그때는 `AGENTS.md`가 들어 있는 안쪽 폴더가 키트 폴더입니다.
1. AI 도구에서 압축을 푼 폴더를 열고 `설치해 줘`라고 요청합니다. AI가 설치 계획을 먼저 보여 주고 확인을 받은 뒤 설치합니다. 설치하는 동안 브라우저에 '로컬 RAG 설치' 화면이 열려 어느 단계를 얼마나 진행했는지 보여 줍니다.
1. 내 프로젝트를 열고 새 대화에서 `/local-rag 이 프로젝트에 적용해 줘`라고 요청합니다. AI가 문서 폴더를 찾아 RAG로 만들고, 프로젝트 지침에 사용법을 적어 둡니다.

설치하면 지금 열려 있는 AI 도구에서도 `rag` 명령을 바로 쓸 수 있게 해 둡니다. `/local-rag`가 목록에 보이지 않으면 새 대화를 열고, 그래도 없으면 AI 도구를 다시 시작합니다.

## 사용 예

| 할 일 | 요청 |
| --- | --- |
| 폴더를 RAG로 만들기 | `/local-rag docs 폴더 파일 모두를 RAG로 만들어 줘` |
| 질문 | `/local-rag [찾을 내용]을 찾아 줘` |
| 목록 확인 | `/local-rag 목록 보여 줘` |
| 파일 하나만 다시 반영 | `/local-rag docs 컬렉션에서 [파일 이름]을 다시 인덱싱해 줘` |
| 조건에 맞는 문서만 갱신 | `/local-rag docs 컬렉션에서 이름이 [단어]로 시작하는 문서만 갱신해 줘` |
| 컬렉션 갱신(바뀐 파일만 처리) | `/local-rag docs 컬렉션을 갱신해 줘` |
| 처음부터 다시 만들기 | `/local-rag docs 컬렉션을 처음부터 다시 만들어 줘` |
| 문서 폴더를 옮겼을 때 | `/local-rag docs 폴더를 [새 위치]로 옮겼어` |
| 검색할 때 자동 갱신 끄기 | `/local-rag [컬렉션] 컬렉션은 질문할 때 자동 갱신하지 않게 해 줘` |
| 컬렉션 지우기(원본 문서는 그대로) | `/local-rag docs 컬렉션 지워 줘` |
| 쓸 수 있는 임베딩 모델 보기 | `/local-rag 어떤 모델을 쓸 수 있어?` |
| 다른 모델로 만들기 | `/local-rag wiki 폴더를 Qwen3 모델로 RAG 만들어 줘` |

컬렉션 이름은 '프로젝트-폴더-해시' 모양(예: `memo1-wiki-3f9a`)으로 정해집니다. 해시는 폴더 경로로 만들어서, 다른 프로젝트에 같은 이름의 `docs` 폴더가 있어도 겹치지 않습니다.
문서를 몇 개 고친 정도는 갱신을 따로 요청하지 않아도 질문할 때 반영됩니다. 바뀐 파일만 다시 처리하므로 오래 걸리지 않습니다.
문서 폴더를 다른 곳으로 옮겼을 때는 새 위치만 알려 주면 됩니다. 내용이 같은 파일은 다시 처리하지 않습니다.

## 임베딩 모델

기본은 Google의 EmbeddingGemma입니다. 검색 품질은 다른 후보와 비슷하고 색인이 가장 빠릅니다. 다른 모델을 쓰려면 설치할 때 "Qwen3 모델로 설치해 줘"처럼 요청하거나, 설치한 뒤에 `/local-rag Qwen3 모델로 바꿔 줘`라고 요청합니다.

| 모델 | 만든 곳 | 크기 | 검색 품질(MRR@5) | 색인 속도 | 메모 |
| --- | --- | --- | --- | --- | --- |
| `embeddinggemma:300m` | Google(미국) | 약 620MB | 0.955 | Qwen3보다 Windows 약 5~9배, Mac 약 2.5배 빠름 | 기본. 한 조각에 2K 토큰까지(키트의 1,000자 조각은 충분). 라이선스는 Gemma 이용 약관, Ollama 0.11.10 이상 |
| `qwen3-embedding:0.6b` | Alibaba(중국) | 약 640MB | 0.900 | 기준 | 이전 기본. 한 조각에 32K 토큰까지 받아 긴 문서도 잘리지 않음. Apache-2.0 |
| `snowflake-arctic-embed2:568m` | Snowflake(미국) | 약 1.2GB | 0.934 | Qwen3보다 Mac 약 1.5배 빠름 | 바탕 모델은 중국 BAAI의 bge-m3. Apache-2.0 |

검색 품질은 한국어 문서 18개와 질문 43개로 잰 결과입니다. 질문 하나가 약 0.02점이라, 세 모델의 차이는 질문 한두 개 차이(Gemma가 6개를 더 맞히고 2개를 더 틀림)여서 비슷한 수준으로 봅니다. 색인 속도는 키트 시험 PC(GitHub의 x64 Windows에서 Qwen3는 초당 0.16~0.31개, Gemma는 1.4~2.5개 조각, Mac)에서 잰 값이며 PC마다 다릅니다.
컬렉션은 만들 때 쓴 모델로 검색하므로, 컬렉션마다 모델이 달라도 됩니다.

## 사내망으로 가져가기

인터넷이 막힌 사내망 PC에는 설치 재료를 미리 받아서 외장 드라이브로 가져갑니다. 한 번 가져가면 사내망 안의 어느 프로젝트에서든 다시 쓸 수 있습니다.

1. 인터넷이 되는 PC에서 외장 드라이브를 연결하고, 키트 폴더를 AI 도구에서 열어 `E 드라이브에 반입용으로 담아 줘`처럼 요청합니다. AI가 사내 PC의 운영체제와 쓸 임베딩 모델을 물어봅니다.
1. AI가 재료를 받고(Windows 기준 약 2.5GB), 외장 드라이브의 `local-rag` 폴더로 복사하고, 복사한 파일을 확인합니다. 진행 상황은 브라우저의 '로컬 RAG 반입 준비' 화면에서 볼 수 있습니다. 이 PC에는 아무것도 설치하지 않습니다.
1. 외장 드라이브의 `local-rag` 폴더 하나만 가져갑니다. 무엇이 들었는지는 그 폴더의 `반입 안내.txt`에 적혀 있습니다.
1. 사내 PC에서 그 폴더를 AI 도구에서 열고 `설치해 줘`라고 요청합니다. AI가 폴더를 홈 폴더로 복사한 뒤, 인터넷 없이 설치합니다.

색인은 사내 PC에서 사내 문서로 새로 만듭니다. 외부에서 만든 색인을 가져가야 하면 요청할 때 "색인도 함께"라고 말합니다. 색인에는 문서 내용 조각이 들어 있으니 반출 규정을 확인합니다.

사내망에서도 AI 도구는 그 서비스(GitHub Copilot 등)에 접속할 수 있어야 합니다. RAG의 색인과 임베딩은 PC 안에서만 동작합니다.

## 새 버전으로 바꾸기

지금 키트 폴더를 AI 도구에서 열고 `최신으로 업데이트해 줘`라고 요청합니다.

| 받은 방법 | AI가 하는 일 |
| --- | --- |
| `git clone` | 같은 폴더에서 `git pull`로 받고 다시 설치합니다. 가상 환경과 색인은 그대로 씁니다. |
| ZIP | 새 ZIP을 받아 홈 폴더의 다른 폴더에 풀고 그 폴더에서 설치합니다. 예전 폴더의 색인은 새 폴더로 가져오며, 확인이 끝나면 예전 폴더는 지워도 됩니다. |

직접 새 ZIP을 받았다면, 압축을 푼 폴더를 열고 `설치해 줘`라고 요청해도 같습니다.

예전 기본 모델(Qwen3)을 그대로 쓰던 PC는 다시 설치할 때 기본 모델이 EmbeddingGemma로 바뀝니다(설치 계획에 "기본 모델 바뀜"으로 나옴). 새로 만드는 컬렉션부터 쓰고, 기존 컬렉션은 Qwen3 그대로 씁니다. 직접 Qwen3를 골랐던 PC나 Ollama가 0.11.10보다 오래된 PC는 바꾸지 않습니다.

## 설치되는 것

| 구성 요소 | 위치 | 하는 일 |
| --- | --- | --- |
| `local-rag` 스킬 | `~/.agents/skills`, `~/.claude/skills`, `~/.copilot/skills`의 `local-rag` | `/local-rag` 요청을 `rag` 명령으로 처리. 여러 AI 도구가 읽는 폴더에 같은 내용을 넣음 |
| `rag` 명령 | 이 폴더의 `bin/`(PATH에 등록) | 폴더 색인, 검색, 갱신, 옮기기, 목록, 삭제, 모델 |
| 바로 쓰는 실행 파일 | Windows는 `%LOCALAPPDATA%\Microsoft\WindowsApps\rag.cmd`, macOS는 PATH에 있는 `~/.local/bin/rag` | 설치 전에 열어 둔 AI 도구에서도 `rag`를 찾게 함 |
| 벡터 DB | 이 폴더의 `indexes/<컬렉션>.db` | RAG로 만든 폴더(컬렉션)마다 파일 하나 |
| 임베딩 모델 | Ollama | 문서 조각과 질문을 벡터로 바꿈 |
| 자동 승인 규칙 | VS Code 사용자 설정, Claude Code 사용자 설정 | 검색, 목록, 미리보기는 승인 없이 실행 |

## 폴더 구성

```plaintext
키트 폴더/
├── README.md              # 이 문서(사람용)
├── AGENTS.md              # AI가 따르는 설치, 반입, 점검 절차
├── CLAUDE.md, GEMINI.md   # Claude Code, Gemini CLI가 AGENTS.md를 읽게 하는 한 줄
├── USAGE.md               # rag 명령과 설치 도우미 사용법(개발자용)
├── models.json            # 고를 수 있는 임베딩 모델과 형식
├── rag.py, bin/           # rag 명령
├── setup/kit.py           # 설치 도우미(설치, 점검, 반입 준비, 복사, 모델 추가)
├── setup/progress.py      # 설치와 반입 준비의 진행 상황 화면
├── skill/local-rag/       # 설치할 때 복사하는 스킬 원본
├── offline/               # 반입 재료(sqlite-vec는 들어 있고, 나머지는 반입 준비 때 받음)
├── tests/selftest.py      # 자체 시험
└── 1-setup.md ~ 4-check-quality.md   # 직접 만들어 보기(강의용)
```

## 주의

- 폴더는 OneDrive, iCloud Drive 같은 동기화 폴더나 다른 프로젝트 폴더 안에 두지 않습니다. 설치할 때 AI가 위치를 먼저 확인합니다.
- 키트 폴더를 옮겼거나 다른 PC에서 가져왔다면, 옮긴 폴더를 열고 다시 `설치해 줘`라고 요청합니다.
- 설치와 색인은 PC에 따라 수십 분 걸릴 수 있습니다. AI 도구가 기다리다 먼저 돌아와 같은 명령을 다시 실행해도 작업이 두 번 돌지 않고, 진행 중인 작업의 진행 상황과 결과를 이어서 보여 줍니다. 중간에 꺼졌으면 끝난 부분은 건너뛰고 이어서 합니다.
- Ollama가 꺼져 있으면(PC를 다시 켠 뒤 등) `rag`가 쓸 때 다시 켭니다.
- VS Code에서 Copilot 하네스 대신 Local 하네스를 쓰면, 처음 `rag`를 실행할 때 승인 창이 뜹니다. 승인 창의 `...` 메뉴에서 `Enable Auto Approve...`를 한 번 켜 두면 검색과 목록은 다음부터 묻지 않습니다(VS Code가 처음 한 번만 직접 확인받는 설정입니다).
- 검색으로 찾은 조각은 AI 대화에 포함되어 그 AI 서비스의 서버로 전달됩니다. AI 서비스에 보내면 안 되는 문서는 RAG로 만들지 않습니다.
- 지금은 `.md`, `.markdown`, `.txt` 파일만 읽습니다. Word나 PDF 문서는 마크다운으로 변환한 뒤 RAG로 만듭니다.

## 직접 만들어 보기(강의용)

`1-setup.md`부터 `4-check-quality.md`까지는 같은 구성을 AI가 처음부터 만들게 하는 단계별 프롬프트입니다.
이 폴더에서 `직접 만들어 보기 폴더를 만들어 줘`라고 요청하면, AI가 단계 파일만 담은 새 폴더를 만들어 줍니다.
그 폴더를 열고 입력창에서 파일을 첨부해(VS Code는 `#`, Claude Code는 `@`) "첨부한 파일의 내용대로 진행해 줘"라고 차례로 요청합니다.

| 파일 | 하는 일 |
| --- | --- |
| `1-setup.md` | Python 가상 환경, sqlite-vec, Ollama와 모델 준비, 이 PC의 임베딩 속도 측정 |
| `2-rag-tool.md` | `rag` 명령 만들기, 자체 시험, PATH 등록 |
| `3-skill.md` | `local-rag` 스킬과 터미널 자동 승인 규칙 |
| `4-check-quality.md` | 컬렉션 하나의 검색 품질 점검(필요할 때) |
